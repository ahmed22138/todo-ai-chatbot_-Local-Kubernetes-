# Quickstart: Deploy Todo AI Chatbot to Kubernetes

**Feature**: Cloud-Native Kubernetes Deployment
**Branch**: `1-k8s-deployment`
**Date**: 2026-01-07
**Target**: Local Minikube cluster

## Overview

This guide provides step-by-step instructions for deploying the Phase III Todo AI Chatbot to a local Kubernetes cluster using Minikube, Docker, and Helm. All steps leverage the Agentic Dev Stack (Gordon, kubectl-ai, kagent) where applicable.

**Estimated Time**: 10 minutes (fresh Minikube cluster to fully deployed system)

---

## Prerequisites

### Required Software

| Software | Version | Installation Check | Install Command |
|----------|---------|-------------------|-----------------|
| **Docker Desktop** | 20.10+ | `docker --version` | https://docs.docker.com/get-docker/ |
| **Minikube** | 1.32+ | `minikube version` | https://minikube.sigs.k8s.io/docs/start/ |
| **kubectl** | 1.28+ | `kubectl version --client` | Included with Docker Desktop/Minikube |
| **Helm** | 3.12+ | `helm version` | https://helm.sh/docs/intro/install/ |

### Optional AI Agents

| Agent | Purpose | Availability Check | Install Command |
|-------|---------|-------------------|-----------------|
| **Gordon** (Docker AI) | Dockerfile generation | `docker ai --version` | Included in Docker Desktop with AI features |

**Note**: If AI agents are unavailable, standard commands are provided as fallback.

### System Resources

- **CPUs**: 2+ (4 recommended)
- **Memory**: 4GB+ (8GB recommended)
- **Disk**: 20GB+ free space
- **Network**: Internet access for pulling base images (Alpine, Nginx, MongoDB)

## Phase 1: Environment Setup

### Step 1.1: Start Minikube Cluster

```bash
# Start Minikube with recommended resources
minikube start --cpus=4 --memory=8192 --disk-size=20g --driver=docker

# Verify cluster is running
kubectl cluster-info

# Expected output:
# Kubernetes control plane is running at https://127.0.0.1:xxxxx
# CoreDNS is running at https://127.0.0.1:xxxxx/api/v1/namespaces/kube-system/services/kube-dns:dns/proxy
```

**Using kagent for cluster health check**:
```bash
# Analyze cluster health (if kagent available)
kagent analyze cluster

# Expected output: All nodes healthy, core addons running
```

**Fallback (without kagent)**:
```bash
# Check node status
kubectl get nodes

# Expected output:
# NAME       STATUS   ROLES           AGE   VERSION
# minikube   Ready    control-plane   1m    v1.28.x
```

---

### Step 1.2: Enable Required Addons

```bash
# Enable Nginx Ingress Controller
minikube addons enable ingress

# Enable Metrics Server (for kubectl top)
minikube addons enable metrics-server

# Verify addons are enabled
minikube addons list | grep -E 'ingress|metrics-server'

# Expected output:
# | ingress                     | minikube | enabled ✅
# | metrics-server              | minikube | enabled ✅

**Using kubectl-ai for addon verification**:

```

**Fallback (without kubectl-ai)**:
```bash
# Check ingress controller pods
kubectl get pods -n ingress-nginx

# Expected output: All pods in Running state
```

## Phase 2: Build and Load Docker Images

### Step 2.1: Generate Dockerfiles

**Using Gordon (Docker AI Agent)**:

```bash
# Frontend Dockerfile generation
docker ai generate dockerfile \
  --context ./frontend \
  --output ./frontend/Dockerfile \
  --base-image node:18-alpine \
  --multi-stage \
  --runtime nginx:alpine \
  --description "React Todo AI Chatbot frontend"

# Backend Dockerfile generation
docker ai generate dockerfile \
  --context ./backend \
  --output ./backend/Dockerfile \
  --base-image node:18-alpine \
  --multi-stage \
  --health-check /health \
  --description "Node.js Todo AI Chatbot backend"
```

**Fallback (if Gordon unavailable)**: Dockerfiles will be AI-generated by Claude using Gordon's patterns (see `/sp.tasks` phase for artifact generation).

---

### Step 2.2: Build Docker Images

```bash
# Build frontend image
docker build -t todo-frontend:1.0.0 ./frontend

# Build backend image
docker build -t todo-backend:1.0.0 ./backend

# Verify images built successfully
docker images | grep todo-

# Expected output:
# todo-frontend   1.0.0   <image-id>   X seconds ago   ~40MB
# todo-backend    1.0.0   <image-id>   X seconds ago   ~90MB
```

**Build Validation**:
```bash
# Test frontend image locally
docker run -d -p 8080:80 --name test-frontend todo-frontend:1.0.0
curl http://localhost:8080
docker stop test-frontend && docker rm test-frontend

# Test backend image locally (requires MongoDB)
docker run -d -p 5000:5000 --name test-backend \
  -e MONGODB_URI=mongodb://host.docker.internal:27017/todos \
  todo-backend:1.0.0
curl http://localhost:5000/health
docker stop test-backend && docker rm test-backend
```

---

### Step 2.3: Load Images into Minikube

**Option A: Load images into Minikube (Recommended)**

```bash
# Load frontend image
minikube image load todo-frontend:1.0.0

# Load backend image
minikube image load todo-backend:1.0.0

# Verify images are available in Minikube
minikube image ls | grep todo-

# Expected output:
# docker.io/library/todo-frontend:1.0.0
# docker.io/library/todo-backend:1.0.0
```

**Option B: Use Minikube's Docker daemon directly**

```bash
# Point Docker CLI to Minikube's daemon
eval $(minikube docker-env)

# Rebuild images (now in Minikube)
docker build -t todo-frontend:1.0.0 ./frontend
docker build -t todo-backend:1.0.0 ./backend

# Verify images
docker images | grep todo-

# Restore Docker CLI to host daemon (when done)
eval $(minikube docker-env --unset)
```

## Phase 3: Deploy Helm Charts

### Step 3.1: Validate Helm Charts

```bash
# Lint all charts
helm lint charts/frontend
helm lint charts/backend
helm lint charts/database

# Expected output: No errors (warnings about missing icon/home URL acceptable)

# Dry-run template rendering
helm template frontend charts/frontend > /tmp/frontend-rendered.yaml
helm template backend charts/backend > /tmp/backend-rendered.yaml
helm template database charts/database > /tmp/database-rendered.yaml

# Validate rendered YAML (if kubectl-ai available)
kubectl-ai "validate these manifests for best practices" /tmp/frontend-rendered.yaml
```

**Fallback (without kubectl-ai)**:
```bash
# Validate with kubectl dry-run
kubectl apply --dry-run=client -f /tmp/frontend-rendered.yaml
kubectl apply --dry-run=client -f /tmp/backend-rendered.yaml
kubectl apply --dry-run=client -f /tmp/database-rendered.yaml
```

---

### Step 3.2: Install Database Chart

```bash
# Install MongoDB (StatefulSet with persistence)
helm install todo-database charts/database

# Wait for database pod to be ready
kubectl wait --for=condition=ready pod/todo-database-0 --timeout=120s

# Verify database is running
kubectl get statefulset todo-database
kubectl get pods -l app.kubernetes.io/name=database

# Expected output:
# NAME               READY   AGE
# todo-database-0    1/1     30s

# Check PVC was created and bound
kubectl get pvc

# Expected output:
# NAME                    STATUS   VOLUME                                     CAPACITY   ACCESS MODES   STORAGECLASS   AGE
# data-todo-database-0    Bound    pvc-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx   5Gi        RWO            standard       30s
```

**Using kubectl-ai for troubleshooting** (if pod fails to start):
```bash
kubectl-ai "why is todo-database-0 not starting?"
# Agent will check logs, events, and describe pod to diagnose issue
```

**Test database connectivity**:
```bash
# Connect to MongoDB from debug pod
kubectl run -it --rm mongo-test --image=mongo:7 --restart=Never -- \
  mongosh mongodb://todo-database-service:27017/todos --eval "db.adminCommand('ping')"

# Expected output:
# { ok: 1 }
```

---

### Step 3.3: Install Backend Chart

```bash
# Install backend API
helm install todo-backend charts/backend

# Wait for backend pod to be ready
kubectl wait --for=condition=ready pod -l app.kubernetes.io/name=backend --timeout=120s

# Verify backend is running
kubectl get deployment todo-backend-deployment

# Expected output:

# {"status":"healthy","uptime":15}
```

**Test backend from within cluster**:
```bash
# Run curl from debug pod
kubectl run -it --rm debug --image=curlimages/curl --restart=Never -- \

# Expected output:
# {"status":"healthy","uptime":30}
```

### Step 3.5: Access Frontend Application

**Via NodePort**:

```bash
# Get NodePort URL
minikube service todo-frontend-service --url

# Expected output:
# http://192.168.49.2:30080

# Open in browser
open $(minikube service todo-frontend-service --url)  # macOS
xdg-open $(minikube service todo-frontend-service --url)  # Linux
start $(minikube service todo-frontend-service --url)  # Windows
```

**Via Port Forwarding** (alternative):

```bash
# Forward local port 8080 to frontend service port 80
kubectl port-forward svc/todo-frontend-service 8080:80

# Access at: http://localhost:8080
```

**Via Ingress** (optional):

```bash
# Get Minikube IP
minikube ip

# Add to /etc/hosts (Linux/Mac) or C:\Windows\System32\drivers\etc\hosts (Windows)
echo "$(minikube ip) todo-app.local" | sudo tee -a /etc/hosts

# Apply Ingress resource (if created)
kubectl apply -f charts/ingress.yaml

# Access at: http://todo-app.local
```

---

### Step 5.3: Common Issues & Solutions

| Issue | Symptom | Solution |
|-------|---------|----------|
| **ImagePullBackOff** | Pod stuck in ImagePullBackOff | Verify image is loaded: `minikube image ls \| grep todo-` |
| **CrashLoopBackOff** | Pod restarting repeatedly | Check logs: `kubectl logs <pod>` and fix application error |
| **Backend can't connect to DB** | Backend readiness probe fails | Verify MongoDB service: `kubectl get endpoints todo-database-service` |
| **Frontend can't reach backend** | API calls fail in browser | Check backend service DNS: `kubectl run -it --rm debug --image=curlimages/curl --restart=Never -- curl http://todo-backend-service:5000/health` |
| **PVC not binding** | StatefulSet pod stuck Pending | Check PVC status: `kubectl get pvc` and describe: `kubectl describe pvc data-todo-database-0` |
| **Ingress not working** | 404 on todo-app.local | Verify ingress addon enabled: `minikube addons list \| grep ingress` and check Ingress resource: `kubectl describe ingress todo-app-ingress` |

**Using kubectl-ai for automated troubleshooting**:
```bash
# Diagnose pod issues
kubectl-ai "why is my frontend pod failing?"

# Diagnose network issues
kubectl-ai "test connectivity from frontend to backend-service"

# Diagnose resource issues
kubectl-ai "which pods are using most memory?"
```

## Phase 6: Upgrades & Rollbacks

### Step 6.1: Upgrade Helm Release

```bash
# Update image tag in values.yaml or use --set
helm upgrade todo-frontend charts/frontend --set image.tag=1.0.1

# Check rollout status
kubectl rollout status deployment/todo-frontend-deployment

# View revision history
helm history todo-frontend
```

---

### Step 6.2: Rollback Helm Release

```bash
# Rollback to previous revision
helm rollback todo-frontend

# Rollback to specific revision
helm rollback todo-frontend 2

# Verify rollback
helm status todo-frontend
kubectl get pods -l app.kubernetes.io/name=frontend
```

## Phase 7: Cleanup

### Step 7.1: Uninstall Helm Releases

```bash
# Uninstall in reverse order (frontend → backend → database)
helm uninstall todo-frontend
helm uninstall todo-backend
helm uninstall todo-database

# Verify releases are removed
helm list

# Expected output: No releases listed
```

**⚠️ Warning**: Uninstalling database release does NOT delete PVC (data persists).

---

### Step 7.2: Delete PVCs

```bash
# List PVCs
kubectl get pvc

# Delete database PVC (data will be lost)
kubectl delete pvc data-todo-database-0

# Verify PVC is deleted
kubectl get pvc

# Expected output: No resources found
```

---

### Step 7.3: Stop Minikube

```bash
# Stop Minikube cluster (preserves cluster state)
minikube stop

# Delete Minikube cluster (removes all data)
minikube delete

# Verify cluster is deleted
minikube status

# Expected output: Error indicating cluster doesn't exist
```
